# Report format

The deliverable. One markdown file, structured for both human reading and downstream programmatic consumption.

## Template

```markdown
# Conformance report

| Field | Value |
|---|---|
| Master | `<path>` |
| Slave  | `<path>` |
| Generated | `<ISO-8601 UTC timestamp>` |
| Workers dispatched | `<N>` |
| Chunks compared | `<M>` |
| Run id | `scc-<timestamp>` |

## Executive summary

- Verified findings: **<count>**
  - high severity: <n>
  - medium severity: <n>
  - low severity: <n>
- Worker findings dropped by verifier: **<count>** (UNGROUNDED: <n>, CONTRADICTED: <n>)
- Second-pass findings raised by verifier: **<count>**
- Overall: **CONFORMANT | DIVERGES IN MINOR WAYS | DIVERGES MATERIALLY | DOES NOT FOLLOW**

One-paragraph plain-English summary of where slave stands relative to master.

## Verified findings

For each finding, sorted by severity desc then by master_location:

### <topic> — <SEVERITY>
- **Type:** MISSING | DIVERGENT | EXTRA
- **Anchor:** `<chunk anchor>`
- **Master** (`<master_location>`):
  > <master_quote>
- **Slave** (`<slave_location>`):
  > <slave_quote>
- **What's different:** <description>
- **Confidence:** high | medium | low
- **Verifier verdict:** VERIFIED | PARTIAL (verifier note: <evidence>)

---

## Second-pass findings (verifier-raised)

Same format as above, but with a `Source: verifier second pass` line.
These are findings the workers missed; treat as medium-confidence by default.

## Integrity section

A short, factual section disclosing the noise floor of this run:

- Worker findings produced: <total>
- Verifier verdicts:
  - VERIFIED: <n> (<pct>%)
  - PARTIAL: <n> (<pct>%)
  - CONTRADICTED: <n> (<pct>%)
  - UNGROUNDED: <n> (<pct>%)
- Verifier-raised second-pass findings: <n>
- Workers that failed (returned invalid output): <n>, anchors: <list or "none">

If UNGROUNDED rate exceeds 20% overall, add a one-line warning: "Elevated
hallucination rate on this run — treat findings with extra scrutiny and
consider re-running the affected workers."

## Methodology

Auto-fill:
- Extraction tool used per source (e.g. "master: markitdown 0.0.1; slave: pdftotext -layout")
- Chunking strategy (A/B/C from `references/chunking-strategies.md`)
- Number of workers and verifier passes
- Coordinator model and skill version

No prose embellishment in this section. Bare facts.
```

## Field discipline

- **Quotes go in blockquote (`>`) form, one per line, no truncation marker for full quotes.** If a quote is truncated to fit the 240-char worker limit, end with `…` to make it explicit.
- **Locations are anchors, not free text.** "Section 2.1.3", "Clause 4.3", "page 12, ¶3", "line 145-150" — all good. "Somewhere in the middle" — not good.
- **Severity is a contract, not a feeling:**
  - high — changes contractual / behavioural / specified meaning. If applied, the change would alter what slave does or means.
  - medium — changes specificity, detail, or scope without flipping meaning.
  - low — formatting, ordering, terminology synonym, stylistic.
- **Confidence is the worker's self-assessment, preserved through to the report.** Do not promote a confidence: low finding to confidence: high during merge. The verifier's verdict can promote certainty separately — that's what the `Verifier verdict` line is for.

## What never appears in the report

- Praise or evaluative summaries of either document's quality.
- Speculation about why the slave diverges (who changed it, when, intent).
- Recommendations on what to fix. The skill audits, it does not prescribe.
- Any reference to the comparison having been done by an AI, model, agent, or tool other than the skill's own neutral name. The Methodology section names the skill and the extraction tools — that is sufficient.
- Emoji.
- Trailing footers, attribution lines, or "generated by" markers.

## Filename convention

`conformance-report-<YYYY-MM-DDTHH-MM-SS>.md` in the user's specified output directory, or in the current working directory if none was specified. Echo the full path back to the user when done.
